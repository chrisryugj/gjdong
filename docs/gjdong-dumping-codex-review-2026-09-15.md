## 1. 종합 판정

아이디어와 분석 깊이는 공모전 소재로 충분하다. 특히 행정자료를 격자 단위로 연결하고, CCTV 효과 주장을 철회한 이력과 한계를 화면에 남긴 점은 강점이다.

현재 그대로 결재선이나 심사위원 앞에 내놓으면 다음 세 가지 질문에서 약해진다.

1. 이 수치가 실제 무단투기 발생을 뜻하는가, 아니면 민원·적발 기록인가?
2. 화면에 표시된 숫자와 근거 그래프·물어보기 답변의 숫자가 같은가?
3. 오늘 승인할 대상·담당·비용·판정일이 무엇인가?

따라서 현재 단계는 **분석 시연본**이며, **정책 결재본·공모전 제출본으로는 신뢰성 문구와 실행계획을 보완해야 한다.**

## 2. 구청장·결재라인 관점

### 강점

- 첫 화면에서 광진구 전체 현황, 지도, 정책 제안, 근거 경로를 한 번에 연결한다.
- 결재용 인쇄 기능과 데이터·방법 모달이 있어 설명 자료로 전환하기 쉽다.
- 정책 제안마다 담당 부서와 검증 방법을 연결하려는 구조가 있다.
- “정책 효과를 사전등록 후 평가한다”는 방향은 결재 문서에 넣을 만하다.

### 부족한 점

#### 2.1 승인할 안건이 한 문장으로 좁혀지지 않는다

정책 카드에는 수거 시간 조정, CCTV 재배치, 전입·다국어 안내, 대학 연계, 공동배출시설 등 여러 안이 함께 있다. 하지만 결재자가 오늘 승인해야 할 범위가 대상지 선정인지, 시범 시행인지, 예산 편성인지 구분되지 않는다.

개선 방향:

- 제목을 “무단투기 감소 대책 시행”이 아니라 “수거시간 조정 시범 대상지·담당부서 협의 승인”처럼 좁힌다.
- 한 장에 `안건 / 주관 / 협조 / 대상지 / 시작 예정일 / 판정일 / 추가 소요 / 중단 기준`을 고정한다.
- “무예산” 대신 “추가 예산 미산정. 인력·이전·안내 비용 확인 필요”로 표시한다.

#### 2.2 분석 결과와 실제 발생을 혼용한다

화면과 답변에서 민원·과태료·순찰 적발이 실제 발생처럼 읽힐 수 있다. 접수·적발 시각은 투기가 발생한 시각이 아니며, 과태료는 신고·단속·행정처리의 영향을 받는다.

“실제 발생”, “전체 발생”, “발생률”은 다음처럼 제한하는 편이 안전하다.

- “민원·과태료 기록”
- “순찰 적발 기록”
- “인구 천 명당 민원 접수 건수”
- “이 분석에서 관측된 적발 분포”

#### 2.3 전망 성능 표시가 검증 범위를 넘어 읽힌다

화면의 “80% 예측구간 적중 83%”는 같은 6개 잔차로 구간 폭과 적중률을 계산한 기록이므로 독립적인 구간 검증으로 보기 어렵다. `명목 80% 근사구간 · 독립 구간 검증 전`을 함께 표시해야 한다.

#### 2.4 운영 절차가 행정 시스템보다 개발 작업처럼 보인다

조치 대장 등록과 갱신이 저장소 JSON 편집·재배포로 설명되면, 심사위원에게는 운영 서비스가 아니라 개발자 시연으로 보인다.

화면에는 등록 담당, 최근 갱신일, 다음 판정일, 변경 이력을 보여주고 저장소 경로는 관리자 문서로 분리하는 것이 좋다.

## 3. 공모전 심사위원 관점

### 강점

- 주소·민원·과태료·건축물·인구 자료를 연결한 문제 정의가 구체적이다.
- CCTV 초기 효과 주장을 철회하고 평균회귀 문제를 설명한 점은 자기검증 사례다.
- 100m 격자, 상주인구·생활인구, 주거 유형 분리 등 반론을 예상한 흔적이 있다.
- 정책 효과를 사후 시범평가로 돌리려는 태도는 과장된 AI 서비스보다 설득력이 있다.

### 심사에서 바로 지적될 위험

#### 3.1 근거 그래프와 본문 결론이 서로 다르다

그래프 원문에는 “무단투기는 시민의식이 아니라 배출 관리주체 부재의 함수”, “민원 증가는 발생 증가가 아니라 앱 보급에 따른 신고편향”처럼 단정적인 문장이 남아 있다. 반면 본문과 최신 답변은 원인·실제 발생을 단정하지 않는다.

그래프의 Claim을 “검증된 주장”으로 표시하는 것도 위험하다. `주장 / 범위 한정 / 철회 / 미확인`을 별도 상태로 분리하고, 그래프와 물어보기에도 같은 정본 문장을 주입해야 한다.

#### 3.2 같은 지표의 정의와 값이 화면마다 다르다

현재 검토에서 이동식 CCTV 264대와 276대, 재활용정거장 857·938·940곳, 과태료 3,247건과 3,124건 등이 서로 다른 화면에서 발견됐다. 중복 제거·위치 매칭 제외·품목 분리 등 정의 차이라면 화면에 명시해야 한다.

심사위원은 숫자 자체보다 “왜 다르냐”를 먼저 묻는다. 각 지표에 `원자료 행수 / 분석 사용 수 / 제외 기준 / 기준일`을 고정 표시하는 것이 필요하다.

#### 3.3 정책 효과가 확인된 것처럼 읽힌다

“줄임”, “효과 없음”, “무예산”, “재배치는 합리적” 같은 표현은 관측 연관과 정책 효과를 섞는다. 현재 분석이 말할 수 있는 수준은 “후보지를 정하고 시범 평가할 근거가 있다”에 가깝다.

## 4. 물어보기 탭 평가

사용자 지적대로 답변이 장황하고 정리가 약하다. 문제는 단순 글자 수보다 구조다.

### 확인한 현상

- 준비된 FAQ는 답변 전문을 기본 펼침으로 보여준다.
- 직접 질문은 본답과 `[부연]`을 분리하지만 부연이 본답을 반복한다.
- 답변 끝에 “다만”으로 시작하는 한계 문장이 반복된다.
- 생성 답변과 고정 FAQ의 문체·길이·근거 표시 방식이 다르다.
- 내부 코드명이나 조치 대장 식별자가 답변에 노출될 수 있다.
- 중단된 스트림이 완성 답변처럼 재사용될 가능성이 있다.
- “그래프에서 노드를 찾는 중” 등 실제 처리 단계와 연결되지 않은 진행 문구가 있다.

### 권장 답변 규격

```text
결론: 한 문장
근거: 핵심 수치 1~2개
한계: 판단을 바꾸는 조건 1개
다음 행동: 정책 질문일 때만 대상·담당·판정일을 한 문장
근거 보기: 자료명·기준일·집계단위
```

권장 길이는 본답 100~140자, 부연 3개 이내다. 본답과 부연에서 같은 문장을 반복하지 않는다. 질문이 단순 현황이면 한계 문장을 억지로 붙이지 않는다.

### 답변 예시

> 다가구·단독주택이 밀집한 곳에서 적발 기록이 많았습니다. 인구 지표를 함께 넣어도 이 관계는 유지됐지만, 그 이유나 실제 감축 효과는 확인하지 못했습니다. 대상 지역을 정해 시범 평가하는 단계가 적절합니다.

근거 수치와 출처는 접어서 보여주고, 답변 생성 모델이 임의의 문서명을 만들지 않도록 허용된 출처 목록을 고정해야 한다.

## 5. UI·UX 개선 제안

### 우선 개선

- 정책 탭 첫 화면에 정책 6건의 이름과 승인할 다음 행동을 배치한다.
- 결재라인용 수치 타일에서 β 대신 “대상 격자 수·기준일·기록 종류”를 먼저 보여준다.
- 물어보기 탭은 모바일에서 지도를 기본 접고 답변 영역을 넓힌다.
- FAQ 15개를 모두 펼치는 구조 대신 결재용 질문 5~6개를 먼저 보여준다.
- 답변 카드에 `결론 / 수치 / 한계 / 다음 행동` 라벨을 넣는다.
- 근거 그래프는 전체 105노드를 기본 노출하지 말고 선택한 결론의 계보만 먼저 보여준다.
- 지도 범례에 “지도 원은 민원, 회귀 결과는 과태료 기준”처럼 지표를 명시한다.
- 3D 막대·숫자 카운트업·호출어 버튼은 시연 효과보다 판독성을 우선해 축소 검토한다.
- 탭 순서는 `정책 제안 → 발견 → 운영·전망 → 물어보기 → 근거 그래프`가 결재 흐름에 더 자연스럽다.

## 6. AI 슬롭·부적절 표현 전수검사 결과

반복되거나 홍보성으로 읽히는 표현이 있다.

| 현재 표현 유형 | 개선 방향 |
|---|---|
| 최강 예측변수 | 가장 강한 연관 요인 |
| 데이터가 뒤집은 것 | 초기 해석과 재검증 결과 |
| 사람을 겨냥하는 대책이 비어 있음 | 정책 목록에서 주민 배출안내 연결을 확인하지 못함 |
| 25개 구 공통의 착시 | 서울 전체 앱 신고도 증가했으며 자치구별 원인은 추가 확인 필요 |
| 무예산·0원 | 추가 예산 미산정, 인력·이전 비용 확인 필요 |
| 우연이 아님 | 통계적 유의성은 인과관계를 뜻하지 않음 |
| 실제 발생·전체 발생 | 민원·과태료·순찰 적발 기록 |
| 무엇이든 물어보세요 | 이 분석의 결과와 대책을 물어보세요 |
| 검증된 주장 | 분석 주장 / 범위 한정 / 철회 / 미확인 |
| 표로는 확인할 수 없는 질문 | 여러 자료의 연결 관계를 점검하는 질문 |

특히 “A가 아니라 B다”, “전혀”, “통째로”, “정밀하게”, “확립해야 한다”가 반복되면 AI가 결론을 과장하거나 발표문처럼 말하는 인상을 준다. 사실·해석·미확인·제안을 문장 단위로 분리하면 자연스러워진다.

## 7. 실행 우선순위

### P0 — 제출·결재 전에 반드시

1. 그래프 원문과 화면 문구를 같은 최신 주장 정본으로 통일한다.
2. CCTV·재활용정거장·과태료·β 값의 정의와 기준일을 통일한다.
3. 물어보기 답변을 결론·근거·한계·다음 행동 슬롯으로 고정한다.
4. 결재용 카드에 담당·일정·비용·판정일을 넣고 “지금 바로”, “무예산” 단정을 제거한다.
5. 실제 발생과 민원·적발 기록을 전 화면에서 구분한다.

### P1 — 시연 품질

1. FAQ와 생성 답변을 같은 카드 구조로 통일한다.
2. 허용 출처 목록과 숫자 검증을 평가 게이트에 추가한다.
3. 390px 모바일에서 지도 접힘을 기본값으로 한다.
4. 근거 그래프를 결론별 계보 중심으로 단순화한다.

### P2 — 표현·마감

1. 내부 개발 용어와 과장 표현을 정리한다.
2. 반복되는 “다만”, 괄호 풀이, 부정 병렬 문장을 줄인다.
3. 애니메이션과 음성 연출을 결재·심사 시연에 맞게 절제한다.

## 최종 권고

이 프로젝트는 “AI가 무단투기 원인을 찾아 해결한다”로 소개하면 약해진다. “행정기록을 연결해 관리 후보지를 좁히고, 정책 효과는 사전등록한 시범사업으로 검증한다”로 소개할 때 분석의 강점과 정직성이 함께 살아난다.
