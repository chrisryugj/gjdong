# 클린광진 상황실 출품 검토 (2026-09-05)

관점: 데이터 아키텍트·온톨로지 설계자로서 심사위원 자리에 앉았을 때 무엇을 묻고 어디서 감점할지.
같은 날 코덱스가 낸 정적 검토([dumping-production-review-2026-09-05.md](dumping-production-review-2026-09-05.md))의 지적은 대부분 타당해 이 세션에서 코드로 반영했고, 반영하지 못한 것은 아래 "남은 일"에 있다.

## 1. 한 문장 포지션

> 광진구의 행정·공공·공간 데이터를 100m 격자에서 연결하고, 신고 편향과 분석 한계를 숨기지 않으며, 근거가 이어지는 정책 제안과 사전등록 평가 설계까지 한 화면에서 이어지는 생활환경 의사결정 시스템.

쓰지 않을 말: "원인을 규명했다", "CCTV 효과를 입증했다", "발생량을 예측한다", "신고 편향을 제거했다", "AI가 답한다".

## 2. 강점으로 내세울 것 (심사 서사 순서)

1. **신고 편향 분해.** 민원 2.10배(연환산)가 앱 2.97배·채널고정 1.11배·단속 적발 0.53배로 갈라진다. 서울스마트불편신고는 서울시 공통 채널이라 25개 구 전부에 같은 착시가 있다. 이 프로젝트가 서울시 차원 시사점을 갖는 지점이고, 채널고정 지표 제안이 곧 정책 제안이다.
2. **관리 구조 가설.** 관리주체 없는 주거 β +0.312, 공동주택 세대수 연관 미확인. "시민의식"에서 "배출 환경"으로 정책 프레임을 옮기는 근거. 대리변수라는 한계를 같이 말해야 신뢰가 산다.
3. **철회의 구조화.** CCTV 효과 주장을 대칭 설계로 재검토해 철회했고, 철회를 지우지 않고 그래프에 `retracted`로 남겼으며, 재발 방지로 사전등록 원칙을 만들었다. 심사에서 가장 드문 자산이다. 화면에서는 발견 탭 맨 위 "기존 해석 vs 이 분석" 6쌍이 이걸 보여준다.
4. **온톨로지가 일을 한다.** 역량 질문 7개가 그래프 위에서 즉시 계산된다. "연관 요인 중 대책이 없는 것"에서 신규 대책 3건이 나왔고, 지금은 "상권 밀집(β +0.086)에 대책 없음"과 "사전등록 원칙이 제안 6건 중 1건에만 연결"이라는 새 공백을 스스로 드러낸다. 스키마(클래스 14·관계 22·도메인/레인지)와 검증기(오류 0)가 있어 "그림"이 아니라 "구조"라고 말할 수 있다.
5. **재현 패키지.** 해시 83개, verify.py, MODEL_SPEC. 단 "모든 수치 재현"이 아니라 "고정 산출물 무결성 + 핵심 수치 대조"로 정확히 말한다.
6. **100m 격자 EPSG:5179.** SGIS 인구격자와 좌표로 바로 조인된다. 다른 구로 옮길 때 격자 정의를 다시 만들 필요가 없다.

## 4. 남은 일 (우선순위 순)

### P0. 공개 레포에 map.json이 그대로 있다
`chrisryugj/gjdong`은 PUBLIC이고 `raw.githubusercontent.com/.../data/dumping/map.json`이 비로그인 200으로 내려온다(185KB, 재배치 후보 20곳 대표주소 포함). 인증 라우트는 프로덕션 API만 막는다. 격자 집계·후보지 주소를 공개해도 되는지는 구청과 정할 문제이고, 안 된다면 이력까지 지워야 한다(`public/dumping/` 시절 커밋 포함). 실무 선택지:
- (a) 공개 가능 판정: 지금 구조 유지, 대표주소를 동 단위로 낮추고 README에 공개 등급 명시.
- (b) 비공개 판정: `data/dumping/*.json`을 레포에서 빼고 빌드 시 비공개 저장소에서 토큰으로 받기(`prebuild` 스크립트, Vercel env `GH_DATA_TOKEN`) + git 이력 정리(`git filter-repo`) + Vercel 재배포.
이 판단 전에는 심사자료에 공개 링크를 넣지 않는다.

### P1. 서울시 데이터가 0종
현재 원천은 구청 내부 6종 + 국토부·KOSIS·행안부·OSM·Open-Meteo. 서울 열린데이터광장 데이터셋이 하나도 없다. 서울시 대회라면 치명적이다. 붙일 후보(키는 이미 `.env.local`에 있음):
- 생활인구(행정동·집계구, `SPOP_LOCAL_RESD_DONG`): 등록인구가 아니라 체류 인구 대비 발생률. 상업지 격자 과대추정 교정. 회귀에 노출(exposure) 변수가 없다는 P1-2 지적의 정답이기도 하다.
- 서울시 정비사업 구역 폴리곤: 공가·관리 공백 통제변수.
- 서울시 자치구 경계·행정동 경계: 지금은 admdongkor 경유. 출처를 서울시로 바꾸면 "서울시 데이터 1종"이 된다.
공고의 필수 데이터군은 원문으로 다시 확인할 것(코덱스가 확인한 2026 빅데이터 활용 경진대회는 5월 접수 마감이라 다른 대회일 가능성).

### P1. 분석 쪽(비공개 저장소) 보강
- 홀트윈터스: 모수 선택 구간과 평가 구간 분리, 기준모형(전년 동월·최근 평균) 대비, 예측구간 적중률.
- 상습격자 KPI에서 앱 민원 제외 버전 병행(채널고정+과태료).
- 생활쓰레기 계열만으로 격자 회귀 재적합(담배꽁초 차량 28% 분리). "은폐 가설" 판정이 유지되는지.
- 온톨로지 결함 8건은 [dumping-ontology.md](dumping-ontology.md) 4절. 특히 KPI 노드 분리·계보 노드 추가·사전등록 restricts 전 제안 연결.
- 노드에 `source/asof/hash` 3속성(PROV 최소형)을 export 시 부착.

### P2. 제품
- 질의응답 고정 평가셋(철회 결론·what-if·집단 지목·미확보 데이터 질문 5종) 자동 실행. 지금은 규칙만 있고 검증이 없다.
- 로그인 rate limit이 인스턴스 메모리라 서버리스에서 전역이 아님. 심사 기간에만이라도 Upstash 또는 Vercel KV.
- 조치 대장이 예시 1건. 실제 등록 1건이라도 있으면 "운영 중" 서사가 된다.
- 지도 캔버스 격자의 키보드·스크린리더 대체 표.

## 5. 심사 예상 질문과 답

| 질문 | 답 |
|---|---|
| 이게 온톨로지인가 | 형식 온톨로지는 아니다. 클래스·관계 정의와 도메인/레인지 검증, 역량 질문 7개가 코드로 있고 화면에서 계산된다. OWL 변환은 닫힌 목록이라 어렵지 않지만 이 규모에서 추론기가 줄 것이 없어 안 했다 |
| 원인을 찾았나 | 아니다. 조건부 연관이다. 가장 강한 것이 관리주체 없는 주거의 대리변수이고, 인구는 회귀에 없다 |
| CCTV는 효과가 없나 | "현재 설계에서 차이를 확인하지 못했다". 초기 주장은 평균회귀로 설명돼 철회했고, 그 철회가 그래프와 화면에 남아 있다 |
| 민원이 두 배면 나빠진 것 아닌가 | 앱 2.97배, 전화·직접 1.11배, 단속 적발 0.53배. 발생 증가로 보기 어렵지만 앱 이용자·중복 신고 자료가 없어 완전히 배제하지는 못한다 |
| 다른 구에 되나 | 격자·스키마·역량 질문·화면은 구 무관. 필요한 건 민원·과태료 내부 자료 2종과 공개 데이터 키. 서울시 생활인구를 붙이면 25개 구 공통 분모가 생긴다 |
| 수치는 재현되나 | 고정 산출물 해시 83개와 핵심 수치 10개 대조. 회귀·DID 재추정은 스크립트로 가능하나 verify.py 범위는 아니다 |
