# 클린광진 상황실 출품 검토 (2026-09-05)

관점: 데이터 아키텍트·온톨로지 설계자로서 심사위원 자리에 앉았을 때 무엇을 묻고 어디서 감점할지.
같은 날 코덱스가 낸 정적 검토([dumping-production-review-2026-09-05.md](dumping-production-review-2026-09-05.md))의 지적은 대부분 타당해 이 세션에서 코드로 반영했고, 반영하지 못한 것은 아래 "남은 일"에 있다.

## 1. 한 문장 포지션

> 광진구의 행정·공공·공간 데이터를 100m 격자에서 연결하고, 신고 편향과 분석 한계를 숨기지 않으며, 근거가 이어지는 정책 제안과 사전등록 평가 설계까지 한 화면에서 이어지는 생활환경 의사결정 시스템.

쓰지 않을 말: "원인을 규명했다", "CCTV 효과를 입증했다", "발생량을 예측한다", "신고 편향을 제거했다", "AI가 답한다".

## 2. 강점으로 내세울 것 (심사 서사 순서)

1. **신고 편향 분해.** 민원 2.10배(연환산)가 앱 2.97배·채널고정 1.11배·단속 적발 0.53배로 갈라진다. 서울스마트불편신고는 서울시 공통 채널이라 25개 구 전부에 같은 착시가 있다. 이 프로젝트가 서울시 차원 시사점을 갖는 지점이고, 채널고정 지표 제안이 곧 정책 제안이다.
2. **관리 구조 가설.** 관리주체 없는 주거 β +0.312, 공동주택 세대수 연관 미확인. "시민의식"에서 "배출 환경"으로 정책 프레임을 옮기는 근거. 대리변수라는 한계를 같이 말해야 신뢰가 산다.
3. **철회의 구조화.** CCTV 효과 주장을 대칭 설계로 재검토해 철회했고, 철회를 지우지 않고 그래프에 `retracted`로 남겼으며, 재발 방지로 사전등록 원칙을 만들었다. 심사에서 가장 드문 자산이다. 화면에서는 발견 탭 맨 위 "기존 해석 vs 이 분석" 6쌍이 이걸 보여준다.
4. **온톨로지가 일을 한다.** 역량 질문 7개가 그래프 위에서 즉시 계산된다. "연관 요인 중 대책이 없는 것"에서 신규 대책 3건이 나왔고, 지금은 "상권 밀집(β +0.086)에 대책 없음"과 "사전등록 원칙이 제안 6건 중 1건에만 연결"이라는 새 공백을 스스로 드러낸다. 스키마(클래스 14·관계 22·도메인/레인지)와 검증기(오류 0)가 있어 "그림"이 아니라 "구조"라고 말할 수 있다.
5. **재현 패키지.** 해시 83개, verify.py, MODEL_SPEC. 단 "모든 수치 재현"이 아니라 "고정 산출물 무결성 + 핵심 수치 대조"로 정확히 말한다.
6. **100m 격자 EPSG:5179.** SGIS 인구격자와 좌표로 바로 조인된다. 다른 구로 옮길 때 격자 정의를 다시 만들 필요가 없다.

## 4. 남은 일 (우선순위 순)

### ~~P0. 공개 레포에 map.json이 그대로 있다~~ → 처리 (2026-09-05 후속 세션)
`data/dumping/map.json`은 AES-256-GCM 암호문(`map.json.enc`)만 커밋하고, 빌드가 Vercel env `DUMPING_DATA_KEY`로 푼다(`scripts/dumping-data.mjs`, `npm run build`가 먼저 decrypt). 평문은 gitignore. 과거 커밋의 `public/dumping/map.json`·`data/dumping/map.json`은 `git filter-repo`로 이력에서 제거하고 main을 강제 푸시했다. GitHub는 도달 불가 객체를 즉시 지우지 않으므로 옛 SHA 직접 조회는 한동안 가능할 수 있다. 확실히 끊으려면 GitHub Support에 GC 요청. 포크·클론은 회수 불가. 재수출 뒤에는 `npm run dumping:encrypt` 후 `.enc`를 커밋한다. 비밀번호 `DUMPING_PASSWORD`는 4자리 숫자라 인스턴스별 rate limit으로는 약하다. 심사 기간 전에 긴 문구로 바꿀 것.

### ~~P1. 서울시 데이터가 0종~~ → 6종 결합 완료 (2026-09-05, 같은 날 후속 세션)

- 생활인구(행정동 31개월·250m 격자): 노출 변수로 넣어도 무관리주거 β +0.312 유지. "인구 통제 없음" 지적의 답
- 의류수거함 479곳: "온상" 통념은 단속 자료에서 뒷받침 안 됨(민원만 약한 연관)
- 목적별 CCTV 25구·스마트불편신고 서울 월별·가로쓰레기통: 25구 맥락, "앱 확산은 서울 전체" 근거

- 결정 레이어: 상습격자 앱 제외판 33→12, 홀트윈터스 롤링 백테스트 MAPE 26%(기존 18%는 낙관)

원래 후보 메모(참고):

### 6.3 강점 서사 순서 (2라운드 갱신)

1. 신고 편향 분해에 **적발 경로 분해**를 더했다. 민원 2.10배 대 채널고정 1.11배, 과태료 0.53배, 순찰 적발 0.49배. 세 개의 서로 다른 관측 채널이 같은 방향이고, 어느 하나도 "실측"으로 과장하지 않는다.
2. 관리 구조 가설(무관리주거 β +0.312)과 노출 통제(생활인구를 넣어도 유지)·격자 민감도(200m에서도 유지).
3. CCTV 철회의 구조화와 사전등록 원칙.
4. 온톨로지가 일을 한다. 클래스 14·관계 24, 검증기 오류 0·주의 0, 역량 질문 8개(PROV 커버리지 포함), 격자 지표와 동 지표를 노드로 분리해 "지표 정의가 둘"이라는 지적을 선제.
5. 재현 패키지(해시 102·수치 10)와 verify.py 범위의 정직한 진술.
6. 100m EPSG:5179 격자와 서울시 원천 6종. SGIS 100m 인구가 붙으면 25개 구 어디서나 같은 파이프라인.

### 6.4 심사 문답 추가

| 질문 | 답 |
|---|---|
| 과태료가 신고와 무관하다고 했는데 | 아니다. 2라운드에서 정정했다. 83%가 신고 유래다. 신고와 독립인 순찰 적발 17%만 따로 보면 연환산 0.49배로 역시 줄었다. 단속 인력 변화 자료가 없어 발생 감소인지 단속 축소인지는 가르지 못한다 |
