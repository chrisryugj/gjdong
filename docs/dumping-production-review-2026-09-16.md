## 2. 시연 중 죽는 것 (P0)

**음성 입력이 프로덕션·로컬 모두 막혀 있었다.** `next.config.mjs`의 전역 헤더 `Permissions-Policy: camera=(), microphone=(), geolocation=(self)`(2026-03-08 도입)가 `/dumping`에도 적용됐다. 음성 기능(2026-09-15 도입)은 이 헤더 아래에서 한 번도 브라우저 정책을 통과한 적이 없다.

실측(Playwright, 가짜 마이크 장치·권한 부여):

| 조건 | `featurePolicy.allowsFeature("microphone")` | `getUserMedia` | `SpeechRecognition.start()` |
|---|---|---|---|
| 헤더 있음(반영 전, 프로덕션과 동일) | false | NotAllowedError | `error: not-allowed` |
| 헤더 제거(대조군) | true | ok | `started-ok` |
| 반영 후(`/dumping`만 `microphone=(self)`) | true | ok | `started-ok` |

화면에서는 마이크 버튼이 보이고(`mic.supported`는 API 존재만 검사) 누르면 곧바로 오류 문구가 뜨거나, 호출어 대기는 켜진 채 무반응이었을 것이다. 음량 막대(`useMicLevel`)는 catch가 삼켜 0에 머문다. 반영: `/dumping/:path*` 항목에 `microphone=(self)`를 추가(같은 키는 뒤 항목이 이긴다), 테스트 `tests/dumping-headers.test.ts`로 고정. 나머지 경로는 그대로 `microphone=()`.

### 11.3 통계 방법 탭 재구성

전에는 카드마다 "쉽게 말하면·이 분석에서는·주의" 줄글 세 문단이었고, 특히 회귀의 "주의"는 문장 여덟 개였다. [methods-stats.tsx](../components/dumping/methods-stats.tsx)로 분리해 8장 모두 같은 슬롯: **어떤 질문에 답하나(한 줄) → 도식 → 쉽게 말하면 → 이 분석의 결과(수치 칸 2~4) → 믿어도 되나(✓ 검증 목록) → 조심할 것(△ 한계 목록) → 해설서 절 링크**. 도식 7종은 숫자 없는 원리 그림(격자 결합·회귀 β 막대(데이터)·DID 평균회귀·채널 배율 막대(데이터)·백테스트 분기별 적중률(데이터)·홀트윈터스 수준+추세+계절·근거 그래프 사슬). 수치는 전부 `facts`·map.json에서. 캡처 `r14-methods-*.png`.

### 11.4 "이 분석"이라는 말

"이 분석"은 구어체 자기지시라 보고서 관례("이번 분석"·"본 분석")와 다르고, 대비 보드 제목 "통념·초기 분석과 이 분석의 차이"에서 특히 어색했다. 화면·프롬프트 문자열 24곳을 "이번 분석"으로 통일(조사 "이"가 붙은 낱말은 제외). "본 분석"은 공문체라 화면 톤(보고체 존댓말)에 안 맞아 쓰지 않았다.

### 11.5 민원·과태료 원이 칸을 넘어 겹치던 것

원은 미터 단위 비례 원(`L.circle`, 반경 8 + 건수^0.6 × 6, 상한 70m)이라 26건부터 제 칸(반지름 50m)을 넘고, 51건 칸은 옆 칸 원과 겹쳤다. 의도된 설계(비례 기호)였지만 100m 격자 위에서는 "어느 칸 값인지"가 흐려진다. 반경 상한을 48m로 낮춰 원이 제 칸을 넘지 않게 하고, 26건 이상은 크기 대신 채움 진하기(0.15→0.55)로 구분. 범례 "클수록·진할수록 많음(원은 제 칸 안)". 큰 값의 비교는 격자 기둥이 맡는다.
